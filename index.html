BAIL MANAGER — MCD v5.1 MERISE — SOURCE A TESTER (révision de la source de contrôle v4.14)

v5.1 : modification textuelle verifiee statiquement. Compilation Mocodo v5.1 non executee ; non verifie : dbdiagram.io, MariaDB.

ECARTS AU STRICT CORRIGES (v4.14 -> v5.0)

  • E1ACCEPTATION_CONTRAT (entité sans identifiant propre, dont le 1er attribut entrait dans la clé) est remplacée par l'association N,N ACCEPTER (DOCUMENT_CONTRAT x UTILISATEUR).
  • E2Fausses clés étrangères supprimées : NOTIFICATION.reference_contexte_notification, HISTORIQUE_OPERATION.type_objet/reference_objet -> associations 0,1 explicites.
  • E3(v5.1) Association PRODUIRE retablie pour tracer explicitement quelle prolongation a produit un contrat successeur (0,1 de part et d autre).
  • E4DOCUMENT_FINANCIER : généralisation exclusive totale RECU / QUITTANCE (remplace le XOR en commentaire et l'attribut type_document_financier).
  • E5MOYEN_ENCAISSEMENT : spécialisation exclusive MOYEN_MOBILE / MOYEN_BANCAIRE (remplace type_moyen et les attributs facultatifs selon le type).
  • E6CONTRAT : spécialisation CONTRAT_REPRIS (date_reprise, solde_reprise).

DONNEES FIGEES CONSERVEES (instantanés datés, pas des dérivés recalculables) :

SOLDE_FIN_CONTRAT.total_* / montant_* (D-14) ; ECHEANCE.montant_loyer / montant_charges_echeance (CTR-10, ARB-03).

CONTRAINTES D'INTEGRITE NON EXPRIMABLES PAR LES CARDINALITES (a porter au MLD/applicatif)

Exclusions entre associations 0,1 d'une même entité

  • CI-X1NOTIFICATION : au plus un contexte parmi INFORMER, PREVENIR, AVISER, CONVOQUER.
  • CI-X2HISTORIQUE_OPERATION : au plus un objet parmi AUDITER, CONSIGNER, JOURNALISER.

Egalités de chemin (cycles du schéma)

  • CI-C1CONTRAT.bien = bien de l'ANNONCE de la DEMANDE_LOCATION d'ABOUTIR (LOUER / ABOUTIR / RECEVOIR / ANNONCER).
  • CI-C2PAIEMENT.contrat = contrat des ECHEANCE affectées (RATTACHER / AFFECTER / GENERER) ; PAI-02.
  • CI-C3RAPPEL.contrat = contrat de l'ECHEANCE alertée (MOTIVER / ALERTER / GENERER).
  • CI-C4QUITTANCE : echeance d'un contrat dont le propriétaire est celui du bien ; RECU : paiement idem.
  • CI-C5ACCEPTER : l'utilisateur répondant est PARTICIPANT du contrat du DOCUMENT_CONTRAT ; version = version courante.
  • CI-C6EMPLOYER : moyen possédé par le propriétaire du bien (CONFIGURER / GERER), compatible avec mode_paiement ; ESPECES sans moyen.
  • CI-C7DOCUMENT_CONTRAT / AVENANT (FORMALISER) : même contrat (DOC-02).
  • CI-C8PRODUIRE : si une prolongation produit un contrat successeur, cette prolongation est ACCEPTEE, le successeur PRECEDE le contrat source, les deux contrats portent sur le meme BIEN, motif_creation = PROLONGATION et date_debut = date_application. Les demandes acceptees sans successeur active restent possibles.

Règles métier (valeurs, états, calculs)

  • CTR-01brouillon : 0 participant ; avant EN_ATTENTE_ACCEPTATIONS : >=1 participant, 100 pct, un seul payeur principal.
  • CTR-03/07/11intervalles demi-ouverts sans chevauchement ; PRECEDER sans cycle, même BIEN ; bascule ACTIF->REMPLACE atomique ; un seul successeur.
  • CTR-10/ECH-03/ECH-05/ECH-06/D-22échéances jamais supprimées, sans statut stocké ; engagée = immuable ; prorata du LOYER : jours calendaires réels, arrondi à l'ariary (0,5 vers le haut), décimal ; charges non proratisées sans validation explicite.
  • CTR-12date_fin_effective = date événementielle (borne exclusive), distincte de date_fin_prevue.
  • DOC-02/AVE-03version principale = max(numero_version) sans avenant ; version d'avenant = max par avenant.
  • EDL-01/02état des lieux courant = le plus récent par type et contrat.
  • DEP-04contrepassation d'un mouvement CONFIRME : même type, sens inverse, cumul <= montant initial, sans cycle (CORRIGER).
  • PAI-09un paiement contesté avant validation ne compte pas ; un encaissement VALIDE reste inchangé sans correction explicite.
  • FIN-03SOLDE_FIN_CONTRAT : instantané à date_calcul, sans mutation après FIGE.
  • ARB-01deux avenants APPROUVE/APPLIQUE d'un même contrat ne modifient pas le même champ à la même date.
  • ARB-10un seul bien : une seule ANNONCE PUBLIEE ; pas d'ACTIF vers ANNULE ; pas deux occupations ACTIF concurrentes.
  • ANN-02annonce bloquée si successeur en attente. RES-01 aucune résiliation ni expulsion automatique.
